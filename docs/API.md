# API.md

## 1. API Style

The application uses Next.js Route Handlers.

Base path:

```text
/api
```

Response format:

```json
{
  "success": true,
  "data": {}
}
```

Error format:

```json
{
  "success": false,
  "error": {
    "code": "ERROR_CODE",
    "message": "Safe user-facing message"
  }
}
```

## 2. Documents

### POST /api/documents/upload

Uploads a PDF or DOCX.

Request:

- multipart form data
- `file`

Success:

```json
{
  "success": true,
  "data": {
    "documentId": "doc_123",
    "status": "queued"
  }
}
```

Errors:

- `INVALID_FILE_TYPE`
- `FILE_TOO_LARGE`
- `UPLOAD_FAILED`

### GET /api/documents

Returns document library.

Response includes:

- id
- name
- type
- status
- pageCount
- createdAt

### GET /api/documents/:id

Returns document metadata and processing state.

### DELETE /api/documents/:id

Deletes a document and its associated resources.

### POST /api/documents/:id/process

Starts or resumes document processing.

Processing stages:

```text
extracting
ocr
chunking
indexing
ready
failed
```

## 3. Chat

### GET /api/documents/:id/chats

Returns chats for a document.

### POST /api/documents/:id/chats

Creates a new chat.

### GET /api/chats/:id

Returns chat history.

### POST /api/chats/:id/messages

Starts an AI response.

Request:

```json
{
  "question": "What is the liability cap?"
}
```

The response is streamed.

The server must:

1. Validate the question.
2. Retrieve relevant evidence.
3. Generate the answer.
4. Extract candidate citations.
5. Verify citations.
6. Stream verified answer content/citation events.
7. Persist the completed or cancelled message.

### POST /api/chats/:id/cancel

Signals cancellation where the transport supports an explicit cancellation route.

Already-generated content must remain saved.

## 4. Search

### POST /api/search

Searches a document or selected documents.

Request:

```json
{
  "documentIds": ["doc_1", "doc_2"],
  "query": "termination provisions"
}
```

Response:

```json
{
  "success": true,
  "data": {
    "results": []
  }
}
```

Every result must retain source document identity.

## 5. Citation

### GET /api/citations/:id

Returns verified citation location information.

Example:

```json
{
  "success": true,
  "data": {
    "citationId": "cit_123",
    "documentId": "doc_123",
    "pageNumber": 21,
    "startOffset": 5300,
    "endOffset": 5410,
    "verified": true
  }
}
```

Page and offsets are generated by application-side location logic, not accepted from the AI.

## 6. Multi-Document Questions

### POST /api/questions

Request:

```json
{
  "documentIds": [
    "doc_1",
    "doc_2"
  ],
  "question": "How do the liability clauses differ?"
}
```

The response must preserve citations per source document.

## 7. Comparison

### POST /api/compare

Request:

```json
{
  "leftDocumentId": "doc_v1",
  "rightDocumentId": "doc_v2"
}
```

Response includes:

- matched sections with side-by-side text,
- additions, deletions, modifications,
- plain-language impact explanations (who it favors, risk level),
- monetary and date changes explicitly detected,
- significance metadata (`high`, `medium`, `low`).

### POST /api/compare/chat

Ask questions about the differences between two contract versions (e.g., "What changed in liability?" or "How does this affect me?").

Request:

```json
{
  "leftDocumentId": "doc_v1",
  "rightDocumentId": "doc_v2",
  "question": "What is the liability cap difference?"
}
```

Returns comparative grounded synthesis with quotes verified independently against both versions.

## 8. Tracked-Change Redlining (Part C Option 1)

### POST /api/redline

Analyzes a plain-language edit request (e.g. "make the liability cap mutual") against a DOCX contract and returns a proposed redline diff.

Request:

```json
{
  "documentId": "doc_123",
  "instruction": "Make the limitation of liability mutual for both parties"
}
```

Response:

```json
{
  "success": true,
  "data": {
    "targetText": "Vendor liability shall not exceed...",
    "revisedText": "Neither party's aggregate liability shall exceed...",
    "explanation": "Made the limitation of liability mutual for both parties.",
    "clauseTitle": "Section 8. Limitation of Liability"
  }
}
```

### POST /api/redline/apply

Applies tracked changes into the DOCX OpenXML archive (`w:ins` and `w:del`) and returns the downloadable binary file.

Request:

```json
{
  "documentId": "doc_123",
  "edits": [
    {
      "targetText": "Vendor liability shall not exceed...",
      "revisedText": "Neither party's aggregate liability shall exceed..."
    }
  ]
}
```

Response:

Binary `application/vnd.openxmlformats-officedocument.wordprocessingml.document` containing real Word tracked changes.

## 9. Agentic Research (Bonus)

### POST /api/agent/research

Request:

```json
{
  "documentIds": ["doc_1"],
  "question": "What are the termination rights?"
}
```

The agent can use registered tools (`search_document`, `get_section`, `list_clauses`). Each tool call produces an execution event for the UI. Hard limit of 5 rounds enforced.

## 9. Agent Limits

Default:

```text
MAX_AGENT_ROUNDS = 5
```

The limit must be enforced server-side.

Malformed tool calls should produce a controlled tool error rather than crashing the request.

## 10. Status Codes

- `200` success
- `201` created
- `400` invalid input
- `404` not found
- `409` conflict
- `413` file too large
- `422` extraction/processing failure
- `429` rate limit
- `500` unexpected server error
- `502` upstream provider error
- `504` upstream timeout

## 11. External Providers

### Gemini

Purpose:

- answer generation,
- summaries,
- comparison explanations,
- agent reasoning.

Environment:

```env
GEMINI_API_KEY=
GEMINI_BASE_URL=
GEMINI_MODEL=
```

### Qdrant

Purpose:

- vector retrieval.

Environment:

```env
QDRANT_URL=
QDRANT_API_KEY=
```

Server-only credentials must never be exposed to the browser.

## 12. API Rules

- Validate all input.
- Keep responses consistent.
- Do not expose stack traces.
- Do not return secrets.
- Do not accept AI-provided citation locations as authoritative.
- Do not allow arbitrary tool execution.
